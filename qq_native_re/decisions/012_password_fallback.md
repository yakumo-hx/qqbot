## 二、三点结论

1. **自愈生效**：踢后约 3.5 s 触发 Worker 重启（含清理残留进程）⇒ `decisions/011` 所述自愈能力已在实战中反复验证。
2. **R4 的环境变量机制生效**：重启出的新进程**继承了** `NAPCAT_QUICK_ACCOUNT`（控制台出现“正在快速登录 2668851638”），R4 方案无误。
3. **失败在服务端，不在本地**：被踢（“登录已失效”）同时使**本地缓存的登录凭据被服务端作废**，故快速登录必然失败、只能扫码。⇒ 这解释了用户观察到的“只有第一次成功”（首测时账号健康、凭据有效）。

## 三、决策：启用密码回退

NapCat 自身提示：密码登录不依赖被作废的缓存凭据。故配置用户级环境变量 `NAPCAT_QUICK_PASSWORD`（或备用的 `NAPCAT_QUICK_PASSWORD_MD5`）。

**安全边界（必须遵守）**：
- 密码**只存于本机 `HKCU\Environment`**，**不进入仓库、不进入任何报告/日志、不得告知任何 agent**；
- 本仓库的一切脚本与文档**只允许判断“是否已设置”，绝不回显或记录其值**；
- 一键脚本已加 `[CHECK] password fallback = SET / NOT SET` 预检（无值输出）。

**不确定项（诚实标注）**：密码登录可能触发设备验证；本机已被视为可信设备（用户观察到“新设备提示”消失），故有希望成功；若失败则回落二维码，**不比现状差**。

## 四、验收判据（下一次被踢）

控制台应依次出现：`正在快速登录 <账号>` →（期望）**不再弹二维码**、bot 自动恢复；若仍失败，记录失败原文并回落扫码。另留意 `14:33:29 [Core] [Login] Login Error, ErrType: 1 ErrCode: 3`（疑似二维码超时）是否再现。
